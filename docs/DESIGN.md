# Pre-IPO Portfolio Platform — Проектный документ

> Онлайн-ресурс для составления профессиональных финансовых портфелей из pre-IPO проектов.
> Целевой пользователь: **финансовые советники** (составляют портфели для клиентов).
> Юрисдикции: **РФ + США** (модель разделения — TBD).
> Статус: проектирование (v0.1).

> **Решения по скоупу (v0.1):**
> - Комплаенс (KYC/AML/accreditation/sanctions) — **вне скоупа MVP**. MVP = research-инструмент.
> - Сделки = **заявки/indication of interest**, без реального исполнения.
> - Юрисдикционная модель не выбрана → проектируем гибко: поле `jurisdiction` закладываем сразу, разделение контуров — позже.

---

## 1. Продуктовое видение

Советник заходит на платформу, **исследует** каталог pre-IPO компаний, **анализирует** их (оценка, риск, сценарии exit/IPO), **собирает портфель** под профиль конкретного клиента и **инициирует сделку/доступ к покупке**. Платформа закрывает весь цикл: research → modeling → construction → execution.

### Ключевое отличие от «обычного» брокера
Фокус не на разовой покупке, а на **портфельном подходе**: диверсификация по стадиям/отраслям/географии, моделирование сценариев, риск-метрики с учётом неликвидности, отчётность для клиента.

---

## 2. Роли и доступ

| Роль | Что делает |
|------|-----------|
| **Advisor** (основной) | Управляет клиентами, собирает портфели, запускает сделки, формирует отчёты |
| **Client** (read-only/limited) | Видит свой портфель, отчёты, подтверждает сделки (опционально) |
| **Analyst** (внутр.) | Наполняет каталог, ведёт данные по компаниям, due diligence |
| **Admin** | Управление пользователями, KYC/AML-флоу, комплаенс, настройки сделок |

Advisor работает в модели **«мой пул клиентов»**: каждый портфель привязан к клиенту.

---

## 3. Функциональные блоки

### 3.1 Каталог pre-IPO проектов
- Карточка компании: оценка (valuation), последний раунд, инвесторы, отрасль, география, стадия, ключевые метрики (выручка, рост, burn rate если есть), дата основания.
- Фильтры/поиск: по отрасли, стадии, размеру оценки, доступности сделки, дате раунда.
- Сравнение компаний (side-by-side).
- Источники данных: на старте — ручной ввод аналитиками + импорт CSV; позже — интеграция с провайдерами (см. §8).

### 3.2 Аналитика и сценарии
- **Сценарное моделирование exit**: IPO / M&A / down-round / write-off с вероятностями → ожидаемая доходность (E[MOIC], IRR).
- **Риск-метрики** с поправкой на неликвидность: ожидаемый срок до exit, illiquidity discount, концентрация.
- **What-if**: «что если оценка вырастет на X% за Y лет».
- Бенчмаркинг против отрасли/стадии.

### 3.3 Конструктор портфеля
- Drag-and-drop / форма: добавление позиций, аллокация (% или сумма).
- Визуализация: распределение по отраслям, стадиям, географии, риску.
- Портфельные метрики: ожидаемая доходность, риск, диверсификация, ликвидностный профиль.
- Шаблоны под профиль клиента (консервативный / сбалансированный / агрессивный).
- Привязка к клиенту, версионирование портфеля.

### 3.4 Сделки / доступ к покупке
- Заявка на участие в сделке (indication of interest) по позиции из портфеля.
- Воркфлоу: заявка → проверка accreditation/KYC → согласование условий → подтверждение → расчёт.
- Статусы сделки, документы (term sheet, subscription docs).
- **Только заявки (indication of interest)** — без реального исполнения/расчёта. Заявка фиксируется, дальше — ручная обработка вне платформы.

## 4. Архитектура (высокоуровневая)

```
┌─────────────────────────────────────────────────────────┐
│                    Web App (Next.js)                      │
│   Advisor UI · Client portal · Analyst/Admin backoffice   │
└───────────────────────────┬─────────────────────────────┘
                            │ tRPC / REST
┌───────────────────────────▼─────────────────────────────┐
│                     API / Backend                         │
│  Auth · Companies · Portfolios · Analytics engine ·       │
│  Deals/Workflow · KYC/Compliance · Reporting              │
└───────────────────────────┬─────────────────────────────┘
                            │
        ┌───────────────────┼────────────────────┐
        ▼                   ▼                    ▼
   PostgreSQL          Object storage        External data
 (core + JSONB)        (docs, reports)       (data providers)
```

- **Монолит-модуль на старте** (Next.js fullstack), с чёткими доменными границами, чтобы позже выделить аналитический сервис.
- **Analytics engine** — отдельный модуль (потенциально Python-сервис), т.к. расчёты сценариев/риска удобнее на Python (numpy/pandas). На MVP — на TS, вынесем при росте сложности.

## 5. Технологический стек

| Слой | Выбор | Почему |
|------|-------|--------|
| Frontend + Backend | **Next.js 15 (App Router) + TypeScript** | Единый язык, быстрый MVP, SSR для SEO каталога, легко масштабировать |
| API | **tRPC** (внутр.) + REST для интеграций | Типобезопасность end-to-end |
| БД | **PostgreSQL** + **Prisma ORM** | Реляционная модель + JSONB для гибких метрик |
| Auth | **Auth.js (NextAuth)** + RBAC | Роли, SSO позже |
| UI | **Tailwind + shadcn/ui** | Быстро, профессиональный вид |
| Графики | **Recharts / visx** | Портфельная визуализация |
| Аналитика (фаза 2) | **Python (FastAPI)** микросервис | Финмоделирование |
| Инфра | **Vercel** (web) + **Neon/Supabase** (Postgres) + S3-совместимое хранилище | Быстрый деплой |
| Очереди (позже) | **Inngest / BullMQ** | Асинхронные сделки, отчёты |

## 7. Комплаенс — ОТЛОЖЕН (вне скоупа MVP)

Решение v0.1: комплаенс **сейчас не реализуем**. MVP — research/portfolio-инструмент,
сделки = заявки. Это сознательно снижает скоуп и риски на старте.

**Что закладываем дёшево уже сейчас (крючки на будущее, без логики):**
- Поле `jurisdiction` (RF | US) на `User`, `Company`, `Portfolio`, `DealRequest`.
- `AuditLog` (полезен и без комплаенса — отладка, история).
- Дисклеймер в UI: «информация не является инвестиционной рекомендацией».

**Что осознанно откладываем (фаза 3, перед реальными сделками):**
- KYC/AML, статусы accreditation / квал. инвестора.
- **Sanctions screening** (OFAC SDN + перечни РФ) — обязателен из-за пары РФ/США.
- Изоляция контуров по юрисдикции, разные правила доступа к сделкам.

> ⚠️ Пара **РФ + США** — высокий санкционный/регуляторный риск для трансграничных
> сделок (OFAC, валютный контроль, broker-dealer лицензии). До запуска РЕАЛЬНЫХ сделок
> обязательна проработка с юристами по ценным бумагам в обеих юрисдикциях.
> На этапе MVP это не блокирует — сделок как исполнения нет.

## 9. План релизов

### MVP (фаза 1) — фундамент
1. Auth + роли (advisor, admin).
2. Каталог компаний (CRUD для аналитика, просмотр+фильтры для советника).
3. Конструктор портфеля (создание, позиции, базовая визуализация).
4. Базовые портфельные метрики (аллокация, диверсификация).
5. Управление клиентами.

### Фаза 2 — аналитика
6. Сценарное моделирование (IPO/M&A/write-off, E[MOIC], IRR).
7. Риск-метрики с поправкой на неликвидность.
8. Сравнение компаний, бенчмаркинг.
9. Отчёты для клиента (PDF/экспорт).

### Фаза 3 — сделки
10. Воркфлоу заявок (indication of interest).
11. KYC/accreditation гейты, документы.
12. Статусы, уведомления, audit trail.

### Фаза 4 — масштаб
13. Интеграции с провайдерами данных.
14. Python-аналитический сервис.
15. Client portal, SSO, мультиязычность.
